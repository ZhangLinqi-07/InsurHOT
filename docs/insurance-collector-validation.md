# 保险信源采集配置与本次实测

本报告包含 2026-10-29 的两轮验证。第一轮采集预览完成于 13:13 UTC，第二轮新增渠道正式入库完成于 14:36 UTC。全量材料入口及历史状态保留在 [source-catalog.json](../industry/source-catalog.json)。生产采集配置在 [sources.json](../industry/sources.json)。入口 HTTP 审计另见 [入口审计报告](insurance-source-audit.md)，两种检查的粒度分别保留。

## 当前已启用范围

当前配置共 95 条具体采集渠道，其中 64 条启用、31 条暂停。64 条均通过项目原生 RSS、JSON 或网页列表解析器的标题、链接和发布日期检查，并全部取得实际 collectSource 成功入库结果。首条正文样本确认 60 条，未确认的四条为金融监管总局统计信息、领导活动，人民银行新闻和保险保障基金新闻。保险保障基金后续样本已确认正文，首条报告仍保留未确认结果。

第二轮新增启用国内 14 条、海外 15 条。国内补入人民银行、中保协、上海保交所、保险保障基金、太保、经济观察网及中国银行保险报等栏目，继续使用项目现有采集器。中保协 XML 的 CDATA 内容可直接被原生网页解析器读取。缺少列表日期的栏目通过原生详情规则读取发布日期。中国银行保险报使用公开频道接口，正文来自其原文网页，没有添加新闻引擎或更改 UI。

海外补入部分监管机构和协会的原站 RSS 或网页栏目，包括英国 PRA、加拿大 OSFI、IAIS、EIOPA、芬兰、挪威、瑞士、澳大利亚等来源。PRA 接入范围为审慎监管出版物订阅，未宣称覆盖其全部新闻与许可栏目。吉尔吉斯采用本地语新闻订阅，英文订阅的人员简介未作为保险新闻启用。波兰保险协会的网页提取会命中 cookie 文案，正式采集采用原生 RSS 所带真实正文。

第二轮候选证据为 `.data/source-validation/phase2-domestic-candidates.json` 与 `phase2-international-candidates.json`，正式预览与入库结果为 `phase2-international-collection1.json` 和 `phase2-final-new-collection.json`。新增批次共写入 87 条，结合第一轮 154 条，数据库保存 241 条，其中 112 条正文确认。新增 87 条包含后来暂停的萨尔瓦多采购订阅三条，这三条与暂停审计保留。

财联社页面响应缺少原生正文提取所需 Content-Type，中国银行保险报监管栏目部分短文会被提取成版权页脚，候选继续停留在 needs_review，未加入启用配置。萨尔瓦多订阅虽然标题日期与正文技术验证成功，但样本均为采购公告，已通过项目原生后台版本检查与审计暂停。当前暂停的 31 条包含 23 个待授权公众号与八条受访问、格式、正文或内容范围限制的 RSS。

同一发布机构的多个栏目通过原生身份字段合并热度参与者。新浪四列、中国银行保险报四列及 Wells Media 两个媒体分别设置相同 signal_group_id，金融监管总局等原有 owner_entity_id 保持不变。Wells Media 归属依据为 [Carrier Management 官方隐私政策](https://www.carriermanagement.com/privacy/) 与 [出版商公告](https://www.insurancejournal.com/news/national/2021/12/11/645304.htm)。修订审计为 `.data/source-validation/phase2-source-groups.json`。种子导入脚本补传数据库已有的 signal_group_id，以便全新部署保留身份配置，重跑仍保留后台既有修改。

目前精确关联到启用采集器的原材料目录入口为 70 个，完整 470 个入口继续保留逐条状态。列表成功、正文确认、实际入库和模型筛选分别记录，64 条成功不代表材料提及的每个网站或每个文档都已经接入。

## 第一轮验证记录

第一轮配置共 65 条具体采集渠道，其中 35 条启用，30 条暂停。35 条启用渠道均使用项目原生 RSS、JSON 或网页列表解析器实测，确认可以取得文章标题、原文链接和可信发布日期。每个渠道抽样一篇正文，其中 33 篇正文确认，2 篇未确认。完整结果保存在 `.data/source-validation/final-enabled.json`，包含逐源列表数量、日期数量、文章样本、正文状态及耗时。这里的 35 条反映第一轮验证覆盖范围，不代表全量目录 470 个入口都已配置为自动采集。

国内启用渠道涵盖金融监管总局八个栏目、中国精算师协会两个栏目、中国政府网最新政策、东方财富保险导读、新浪保险四个栏目，以及平安、人保、中国再保、中国人寿官网新闻。海外渠道包括日内瓦协会、Insurance Journal、Carrier Management、Reinsurance News，及在材料中定位到的部分监管机构和行业协会 RSS。综合监管与政府来源仍须经过保险行业预筛，不能将银行、证券或普通政务新闻直接视为保险事件。

## 金融监管总局正文

金融监管总局原文网页通过 JavaScript 加载正文。本项目增加独立保险模块，从原站公开 `SelectByDocId` JSON 的 `data.docClob` 读取正文，继续保留人类可读原文 URL。规章栏目首篇已确认 6046 字正文，政策、解读、征求意见等栏目也取得真实正文。多个栏目中相同 docId 统一使用仅含 docId 的原文 URL，依项目共有身份规则去重。

统计信息首篇为附件型披露，领导活动首篇为短文，这两篇未达到正文确认阈值，保留 `bodyStatus=unconfirmed`。附件及 PDF 的具体内容没有被冒充为已读取。模块每五分钟最多补十篇，采集安全阀严格为 `true` 时才排程。每篇请求前记录尝试进度，未尝试及最早尝试的文章优先，从而让暂时无法提取的文章也能轮转，不阻断后续正文补齐。

## 第一轮暂停渠道

23 个微信公众号保留用户材料中的 ghid，当前暂停，等待可用且获授权的公众号采集服务配置。Camel 的语言模型密钥只用于模型服务，不能代替公众号采集凭据。

其余暂停的七个 RSS 候选包含 Artemis 的 HTTP 403、Qatar Financial Centre Regulatory Authority 的空 feed、澳大利亚保险协会与赞比亚保险养老金局的空 feed、伯利兹与巴拿马入口的样板内容，以及北马其顿保险监督机构首篇正文未确认。样板 feed 即使返回 HTTP 200 且能解析日期，也没有被启用为真实保险资讯。其余未完成具体栏目映射的入口继续保留在全量目录中。

## 第一轮入库与复查方法

本次已对全部 35 条启用渠道实际调用 `collectSource` 写入本地生产试跑库，并保留每源的 `found`、`created`、`revised` 与 `collection.status`。首轮 34 条成功，新西兰保险协会在预览阶段发生一次 25 秒网络超时，首轮脚本按约定退出为失败。原始记录保存在 `.data/source-validation/production-collection.json`，随后只隔离补测该来源，正式采集成功，补测记录保存在 `.data/source-validation/production-collection-retry.json`，未覆盖原始失败。

截至 2026-10-29T13:20:40Z，合并补测后 35 条渠道均取得正式采集成功结果，本轮新增 124 条材料，修订 0 条。结合此前十个渠道试跑已存的 30 条，数据库共保存 154 条材料，每个启用渠道至少有一条材料。重复抓取会继续收取首次三篇导入之外的新近文章，因此第二轮某些渠道的新增超过三篇。这些数字表示实际写入材料的数量，不表示模型筛选正确率、正文完整率或已公开精选数量。汇总及逐源库内计数保存在 `.data/source-validation/production-collection-summary.json`。

本轮采集进程将模型调用安全阀关闭，没有启动 worker。采集产生的后续处理通过项目原生任务入口排队，后续模型试跑独立进行。数据库读写正常，本轮没有重启数据库或站点服务。

同时已将源文件与数据库中 65 个信源逐字段对账。35 个启用信源没有配置漂移，15 个暂停公众号的主体归属，以及其中 12 个公众号的 `publisherRole`，与首次初始化版本有差异。对账保存在 `.data/source-validation/seed-drift.json`，本次检查没有覆盖数据库中的后台配置。

随后在本机初始化阶段，仅同步了保持暂停且没有文章的信源配置，记录位于 `.data/source-validation/paused-initial-sync.json`。没有更改启用信源或已有文章的采集配置，最终一致性复核结果另保存在 `.data/source-validation/final-config-consistency.json`。

在仓库根目录运行 `node scripts/insurance/local-node.mjs scripts/insurance/validate-sources.ts` 可复查全部已启用渠道。`--ids` 接受逗号分隔的信源 ID，`--all` 包含暂停候选，`--out` 指定报告文件。默认检查只读取公开内容，不直接调用模型，不使用付费正文兜底。`--collect` 才把列表送入项目正式采集入口，需要已迁移和初始化的数据库。

报告分别记录列表状态、`bodyStatus` 和 `collectionStatus`。列表成功不会改写正文未确认结果，正式采集返回失败时脚本退出码也为失败。`node --env-file=.env scripts/insurance/enrich-nfra.ts --limit 3` 可单独补齐有限篇 NFRA 正文，该命令只写入共享材料入口并排入正常处理队列，不直接调用语言模型。

所有渠道保持站内全文与全文再分发开关关闭，公开页面展示摘要及原文链接。首次导入每源最多三篇以控制本地试跑规模。生产频率和样本规模应结合实测更新节奏与模型费用调整，人工筛选金标准尚待用户标注。
