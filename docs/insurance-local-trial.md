## 信源覆盖与实际入库

三份材料的 541 行原始记录全部保留在 [source-catalog.json](../industry/source-catalog.json)，归并为 470 个入口。这些入口包含主页、名录、披露起点和待定位栏目，不能全部直接启用为新闻列表。

[sources.json](../industry/sources.json) 当前配置 95 条具体采集渠道，其中 64 条启用、31 条暂停。第一轮启用 35 条，第二轮接入 29 条经过验证的渠道。64 条均通过项目原生解析器的标题、链接和日期验证，60 条确认了首篇正文。金融监管总局统计信息与领导活动、人民银行新闻和保险保障基金新闻的首条样本未确认正文，附件、短文及详情限制保留在证据内。首条未确认不代表整个栏目无正文，保险保障基金第三条样本已取得正文。

64 条启用渠道均已实际调用 collectSource 并成功入库，数据库累计 241 条材料，其中 112 条已有确认正文。第一轮保留的 154 条没有清空，第二轮新增 87 条。87 条中包括后来因采购公告范围不符而暂停的萨尔瓦多来源三条，原始材料继续保留。首轮新西兰 ICNZ 遇到一次网络超时，隔离补测成功，失败与补测记录分别保留。完整结果见 [采集验证说明](insurance-collector-validation.md)，入口探测结果见 [信源入口审计](insurance-source-audit.md)，逐条配置关联见 [source-runtime-map.json](../industry/source-runtime-map.json)。

23 个公众号缺少授权采集服务配置，当前全部暂停。另外八条 RSS 因空结果、样板内容、访问拒绝、正文不足或内容范围不符暂停。财联社候选与中国银行保险报监管栏目尚未通过正文可靠性检查，继续保留为待核验候选。材料中提到的历史在用状态与旧系统运营数字没有写成本机现状。第一份材料引用的逐条状态说明文件没有随本次材料提供。

当前精确关联到启用采集配置的材料目录入口为 70 个。主页与同栏目接口可以对应同一个采集器，64 个启用采集器与 470 个目录入口属于不同口径。其余入口仍保留逐条状态，未视为全部接通。

新浪四个栏目、中国银行保险报四个栏目以及 Wells Media 旗下两个媒体，通过项目原生 signal_group_id 分别归为同一发布机构。金融监管总局、精算师协会、中保协原有 owner_entity_id 归属继续使用，独立监管机构与协会保持各自身份。该调整避免同一发布机构重复增加热点热度，没有修改热点算法。seed 同时补传这一现有字段，使新部署能保留相同分组。

## 真实模型链路

Camel 配置从本机已有的 InsuranceTown 配置中读取并保存在本站 `.env`，未写入 Git。模型为 gemini-3.8-flash，接口为 `https://api.camel-hub.cn/v1`。模型目录验证和真实调用均成功。

第一轮八篇公开文章与第二轮三批共 37 篇累计处理 45 篇，全部达到终态。其中 32 篇通过相关性筛选，13 篇被拦截，形成 32 篇可读内容、7 篇精选和 6 个事件。Gemini 共完成 176 次调用，回执记录输入 681718 tokens、输出 98146 tokens，服务未返回费用字段，不能据此声称实际账单金额。原始响应、使用量和失败回执保存在本地数据库。该样本只验证工程链路，不能据此判断筛选准确率。

当前热点榜有 1 个符合原生条件的条目，尚未生成日报。初次回灌与原始发布时间保持原值，本次运行时间也已晚于当日 08:00 的成刊窗口。当天窗口没有已评判材料时，系统会保留缺期状态。

原始试跑记录位于 `.data/trial/initial-report.json` 和 `.data/trial-run.log`。最初报告查询引用了当前数据库不存在的字段，修复后的补充报告为 `.data/trial/latest.json`，直接读取既有分析并完成归组，重复文章分析调用数为零。首次归组还继承了本机全局百炼向量配置，接口以账户欠费拒绝请求。该失败回执保留，当前通过本站启动器隔离可选服务，使用框架的文字召回完成归组。

第二轮分批记录为 `.data/trial/phase2-batch1.json`、`phase2-batch2.json` 和 `phase2-batch3.json`，累计汇总为 `.data/trial/phase2-summary.json`。汇总保留批次路径与 SHA-256，原始分析和公开编辑修订分别保存，没有重新付费分析同一篇文章。

## 本机运行

当前 API 与网页进程用于浏览试跑结果，后台 worker 未持续启动。自动采集和模型阀在 `.env` 中保持关闭，避免有限试跑自行扩展为持续付费任务。本次实际调用通过单独的、有界试跑进程执行，模型预算为每分钟 60 次、每小时 150 次、每天 200 次。

停止和重新打开本地页面可以在项目目录运行下面的 PowerShell 命令。

```powershell
.\scripts\insurance\stop-local.ps1
& .\.data\runtime\node.exe scripts/insurance/start-local.mjs
```

启动器保留 WSL PostgreSQL 的前台宿主，数据库使用独立的 insurhot 用户和数据库。Windows 本地 Node 位于 `.data/runtime/node.exe`。这些本机运行文件与凭据均在 Git 忽略范围内，迁移到其他机器时应按上游部署文档重新准备环境。

需要再次验证采集或执行有限模型试跑时，通过本站启动器运行，避免继承机器上其他项目的可选付费服务凭据。

```powershell
& .\.data\runtime\node.exe scripts/insurance/local-node.mjs --collect scripts/insurance/validate-sources.ts
& .\.data\runtime\node.exe scripts/insurance/local-node.mjs --collect --models scripts/insurance/trial.ts --analyze 8
```

确认持续运行范围与费用预算后，可用相同启动器在前台运行 worker，并保留终端以便正常停止。

```powershell
& .\.data\runtime\node.exe scripts/insurance/local-node.mjs --collect --models apps/worker/src/main.ts
```

## 仍由使用者决定

精选偏好已确认为尽量广收、减少遗漏，人工标注文章仍用于后续校准门槛。微信公众号采用哪种授权服务以及相应预算尚未确定。向量接口为可选项，当前无需另一个服务即可运行，但文字召回的事件候选覆盖可能较低。

持续运行的机器、域名、采集范围与每日模型预算仍待确定。本机已经保存待处理材料，启动付费 worker 后会继续处理。使用规则与隐私说明保持草案状态，运营主体、联系方式、正式生效时间和再分发许可需要在公开上线前由使用者确认。站点当前仅本机访问，未公开发布。
