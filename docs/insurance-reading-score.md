# 分类后的新闻阅读价值评分

分类与评分分别执行。当前关键词分类结果已经保存后，使用 `scripts/insurance/score-classified.ts` 单独发起 Camel 评分任务。本任务读取已有的公开新闻标题、摘要和类别，保留分类结果、原有结构抽取及新闻身份，不调用分类器、正文理解、写作或归组模型。

## 提示词与顺序

使用者提供的《新闻AI评分提示词.txt》原文保存在 `industry/prompts/reading-score.md`。模型只接收标题与摘要，分别输出整数 `impact`、`information`、`usefulness` 和 `total`，上限为 40、30、30 和 100。程序校验维度范围、整数类型以及三项之和。类别、来源名称、全文、旧分数、关键词命中分均不发送给模型。

每条新闻沿用两次独立评分。第二次收到相同的标题摘要，不包含第一次答案。两个总分的平均值向下取整后写入阅读价值分。批次沿用此前的来源顺序，先处理明确列入国内范围的来源，再处理其他来源，同一范围内按原文发布时间从新到旧，时间相同按文章 ID 排序。来源范围使用 `source-scope.ts` 已有映射，不从中文内容推定属地。

本步骤只更新阅读价值分和评分依据，不重新决定精选、发布日期、事件归属或日报条目。原有精选门槛和结构抽取继续保留。完整分析的历史评分原样保存在分析记录中，当前公开投影优先读取这次标题摘要对应的新评分，人工评分更正优先。

## 执行与恢复

先运行 `node scripts/insurance/local-node.mjs scripts/insurance/score-classified.ts` 生成固定清单。输出会给出清单文件地址、新闻数量、至少需要的模型请求数、模型名称和 Camel 主机。只有已公开、已有分类且有摘要的新闻进入清单。清单包含当时的标题、摘要和类别及其输入哈希。

使用 `node scripts/insurance/local-node.mjs --models scripts/insurance/score-classified.ts --manifest <清单文件> --run` 执行。`--limit <整数>` 可以限制本次处理的清单条数，后续仍用同一清单恢复。已成功保存的新闻直接复用结果，半途失败时通过现有回执复用已返回的第一份答案。

实际请求使用本站已配置的 Camel 地址和评分模型，批次在发送前检查主机及模型与清单一致。所有请求经过原有回执、预算和熔断。预算、停用、拥塞、服务不可用或结果未知会停止批次并记录原因，不自动扩大预算。未配置 Camel 单价时金额估算留空，保存服务返回的实际 tokens。

执行过程中若标题、摘要或类别变化，固定快照的结果会保留作审计，当前新闻不会被旧快照覆盖。重新准备清单后可对更新后的新闻评分。读者打开页面只读取已保存结果，不触发付费请求。

## 记录与展示

`insurance_reading_scores` 保存输入快照、提示词版本、模型、两次维度分及总分、两张回执和最终分数。`publications.score_evidence` 保存当前投影所用的评分依据，后台内容诊断可以展开查看。新增迁移只创建评分表和可空依据字段，不删除旧新闻、分类或分析数据。

批次清单和逐条进度保存在 `.data/reading-score/`，最终分数使用网页、RSS、API 和 MCP 原有的 `score` 字段展示。新闻的关键词分类依据继续独立保存在 `classification` 字段，二者的分数含义分别维护。
